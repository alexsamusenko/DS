# Model Card: L4 GradientBoostingRegressor (демонстрационная модель)

## Назначение
Прогноз урожайности `Ŷ_{m,y}` по мультимодальному вектору признаков (`docs/chapter2/prediction_model.md`, §2.3). Используется в `service/routers/prediction.py` (кешируется в памяти после первого запроса) и в `src/ds_prediction/build_demo.py`.

## Архитектура и базовая модель
`sklearn.ensemble.GradientBoostingRegressor`, параметры по умолчанию из `src/ds_prediction/model.py::make_model()` (`n_estimators=150, max_depth=3, learning_rate=0.05`). Без предобучения — обучается с нуля на каждом запуске.

## Данные обучения
Контролируемый синтетический набор `ds_prediction.synthetic.generate_dataset()`: 30 полей × 5 лет = 150 наблюдений, известная функция формирования урожайности, зависящая от всех 4 модальностей и скрытого эффекта плодородия поля. Не реальные данные — см. `docs/chapter2/prediction_model.md`, §2.3.7, про необходимость эталона для проверки ошибки.

## Гиперпараметры
См. `src/ds_prediction/model.py`. Формальное обоснование выбора ансамблевого метода — `docs/chapter1` (§1.3.1, устойчивость к разнородным по масштабу признакам).

## Метрики
На синтетических данных (`GroupKFold` по `field_id`, 5 фолдов): RMSE ≈ 3.7 (все модальности) против 3.9–9.7 при исключении любой отдельной модальности (см. вывод `python3 -m ds_prediction.build_demo`). Значения меняются от запуска к запуску (случайное разбиение фолдов), порядок величин стабилен.

## Известные ограничения
- Обучена и проверена только на синтетических данных — не отражает реальную сложность зависимостей.
- Не откалибрована по реальным ценам/регионам.
- Не проверена на данных, содержащих реальные пропуски (в отличие от L3, здесь предполагается уже очищенный вход).

## Дата и статус
Создаётся заново при каждом запуске (`_get_model()` в `service/routers/prediction.py`, кеш в памяти процесса) — не персистентная модель. Постоянное хранилище моделей и переобучение на реальных данных хозяйства — задача главы 4, не реализовано.
