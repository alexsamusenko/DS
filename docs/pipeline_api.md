# Сквозной пайплайн DS: контракт API (первый интеграционный срез)

## Маршрут

`POST /pipeline/runs`

Маршрут зарегистрирован в существующем FastAPI-приложении и использует ту же защиту API-ключом, что и остальные бизнес-маршруты.

## Вход

- `farm_id`, `season_id`, `crop`: идентификаторы хозяйства, сезона и культура.
- `fields[]`: уникальные `field_id`, уникальные целочисленные `plot_id`, площадь в гектарах; опционально геометрия WKT, инженерные признаки и коэффициенты кривой отклика.
- `observations[]`: идентификатор наблюдения, поле, переменная, значение или `null`, единица, время и источник.
- `economics`: цена урожая в рублях за центнер, цена удобрения в рублях за кг, необязательный денежный бюджет в RUB и/или ограничение количества удобрения в кг.
- `response_model_evidence_status`: должен быть `validated` для не-синтетической оптимизации. Для демонстрационного запуска можно передать `synthetic` вместе с `options.synthetic_only=true`.
- `gapfill`: необязательная пространственно-временная матрица; требуется при наличии пропусков/отклонённых наблюдений. Размеры матриц должны соответствовать спискам полей и временных точек. `observation_cells` отображает ID наблюдения на [индекс строки, индекс столбца].
- `options`: `synthetic_only`, `export_requested`, `human_approved`, `allow_synthetic_geometry_export`.

## Этапы и результаты

1. **intake** — проверка структуры, уникальности идентификаторов и ссылок на поля.
2. **ontology** — создание изолированной OWL-схемы и сущностей полей. На этом этапе ещё не производится полноценное сопоставление всех наблюдений с ABox и запуск reasoner.
3. **quality_gate / gapfill** — если пропусков нет, этап отмечается как прошедший проверку отсутствия null/rejected. Если пропуски есть, без матрицы этап блокируется; с матрицей вызывается существующий `ds_preprocessing.fill_gaps`. Не восстановленные значения блокируют последующие этапы.
4. **predict** — в текущем срезе разрешён только в явно синтетическом режиме, с фиксированным демонстрационным набором, GroupKFold по полю и сравнением GradientBoostingRegressor с LinearRegression. Если кандидат не лучше baseline, прогнозы не выдаются. Реальный режим заблокирован до регистрации происхождения и валидации модели на реальных данных.
5. **optimize** — использует только явно переданные `baseline`, `R`, `s` для каждого поля. Общий урожайностный прогноз не считается причинной моделью отклика на удобрение. Денежный бюджет переводится в количество через цену удобрения; применяется более жёсткое из денежного и количественного ограничений.
6. **decision** — рекомендации формируются только при успешной оптимизации. Синтетические рекомендации маркируются как exploratory; не-синтетические остаются draft до подтверждения человеком.
7. **isoexport** — экспорт разрешается только для тестового синтетического сценария с явными флагами одобрения и synthetic geometry. Он содержит сгенерированную геометрию и не предназначен для управления реальной техникой.

## Ответ

Ответ содержит `run_id`, общий `status` (`ok`, `blocked`, `error`), `recommendation`, список `stages[]` с отдельными статусами/причинами/предупреждениями, а также `lineage.input_fingerprint` и время создания. Отказ от рекомендации представлен `recommendation.status=withheld` и пустым `actions`.

## Пример минимального заблокированного сценария

См. `examples/three_fields_synthetic_case.json` в предыдущем пакете проектирования. Минимальный корректный запрос без признаков и коэффициентов отклика должен завершаться блокировкой, а не выдачей выдуманной дозы.

## Текущие ограничения

- Это первый интеграционный срез, не подтверждение производственной готовности.
- Наблюдения пока не записываются в долговременный граф онтологии.
- Восстановленная матрица возвращается в результате этапа; она не переписывает исходные наблюдения в хранилище.
- Прогнозы на реальных данных заблокированы до реализации model registry с происхождением данных, метриками, версией и подтверждённым режимом оценки.
- Кривая отклика — однофакторная модель; совместная оптимизация нескольких нутриентов с общим бюджетом не реализована.
- ISOXML проверяется текущими тестами как XML и по отдельным инвариантам; официальное соответствие XSD/AEF и совместимость с конкретным терминалом не заявлены.
