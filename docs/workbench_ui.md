# Тестовый центр принятия решений АПК

Новая вкладка **Центр решений АПК** в существующем React-приложении.

## Локальный запуск

```bash
pip install -e '.[dev]'
uvicorn service.app:app --reload --port 8000
cd frontend && npm ci && npm run dev
```

Открыть http://localhost:5173 и вкладку «Центр решений АПК».

## Поддерживаемые входы

`POST /workbench/files` принимает один файл в multipart-поле `file`: CSV, TSV, XLS/XLSX, JSON, PDF, DOCX, ODT, TXT, JPG/JPEG, PNG, TIF/TIFF. Лимит 20 МиБ на файл. Файлы сохраняются в `DS_WORKBENCH_DIR` (по умолчанию `build/workbench_uploads`) под случайными именами, без исполнения и без публичного URL. Ответ содержит SHA-256, тип, размер, статус `registered_untrusted` и `pipeline_ready=false`.

CSV/TSV: заголовки и до пяти строк для просмотра. JSON: тип корневого объекта и ключи. Для XLSX/PDF/DOCX/изображений извлечение содержания **пока не реализовано**. Это сознательная граница MVP, а не фиктивная поддержка OCR или распознавания агрономических фактов.

Вкладка позволяет вручную редактировать структурированный JSON и запускать `POST /pipeline/runs`, после чего показывает этапы, блокировки, рекомендации и полный JSON. Загруженные файлы пока **не подключены** к нормализации наблюдений или расчётам автоматически.

## Научные и эксплуатационные ограничения

- Не переносить содержимое непроверенного документа в агрономическую модель без верификации единиц, времени, координат, культуры и источника.
- Не выдавать синтетическую демонстрацию за проверенную производственную рекомендацию.
- Текущая версия хранит файлы локально и не обеспечивает антивирусную проверку, управление жизненным циклом файлов, шифрование, изоляцию арендаторов и ролевой доступ. Не размещать открыто в интернете и не загружать чувствительные производственные документы.
- Для полноценного сценария далее нужны: парсеры XLSX/PDF/DOCX, OCR изображений, реестр документов, ручная верификация извлечённых значений, построение признаков, модельный реестр, журнал утверждения решений.
