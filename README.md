# DS — практическая часть диссертации

Прототип программного комплекса для комплексного анализа слабоструктурированных агрономических данных. Архитектура и диаграммы: см. опубликованный артефакт «Архитектура DS» (ссылка — в переписке); формальные постановки и код в этом репозитории следуют её нумерации уровней (L0–L6).

## Статус

| Уровень | Описание | Статус |
|---|---|---|
| L2 | Семантическая интеграция: динамическая онтология, граф знаний | формализовано + прототип (`docs/chapter2_ontology_model.md`, `src/ds_ontology/`) |
| L3 | Комбинированная предобработка: детекция аномалий + кригинг + временной тренд | формализовано + прототип (`docs/chapter2_preprocessing_model.md`, `src/ds_preprocessing/`) |
| L0–L1, L4–L6 | Источники, сбор, аналитика, решения, интерфейс | не начаты |

## Структура

```
docs/
  chapter2_ontology_model.md   -- формальная модель O_t = <C, R_O, R_D, Ax, I, tau> (§2.1)
  datasets.md                   -- открытые источники данных по уровням архитектуры
src/ds_ontology/
  schema.py                     -- TBox: классы, отношения, аксиомы (owlready2 / OWL 2 DL)
  integration.py                -- mu = phi (union) lambda: интеграция структурных и текстовых источников
  build.py                      -- демонстрационная сборка ABox на игрушечных данных
src/ds_preprocessing/
  anomaly.py                    -- детекция аномалий по MAD на остатках после снятия тренда (§2.2.2)
  spatial.py                    -- пространственная оценка обыкновенным кригингом (pykrige, §2.2.3)
  temporal.py                   -- временная оценка (полином + LOOCV-дисперсия, §2.2.4)
  combine.py                    -- комбинирование по обратной дисперсии + валидация входа (§2.2.5)
  validation.py                 -- проверка форм/типов/содержимого входных данных
  synthetic.py                  -- контролируемые синтетические данные для валидации (§2.2.6)
  build_demo.py                 -- сравнение RMSE: пространственный / временной / комбинированный
tests/
  test_schema.py                -- smoke-тесты + проверка консистентности ризонером HermiT
  test_preprocessing.py         -- тесты алгоритма восстановления + валидации входных данных
```

## Запуск

### Локально (Python)

```bash
pip install -r requirements.txt
PYTHONPATH=src python3 -m ds_ontology.build         # соберёт build/agro_demo.owl
PYTHONPATH=src python3 -m ds_preprocessing.build_demo  # сравнение RMSE методов восстановления
python3 -m pytest tests/ -v
```

### В Docker

Не требует локального Python/Java — только Docker.

```bash
docker compose build
docker compose run --rm ds                                  # демо-сборка -> ./build/agro_demo.owl
docker compose run --rm ds python3 -m pytest tests/ -v       # весь набор тестов, включая ризонер HermiT
```

`./build/` на хосте примонтирован в контейнер, поэтому `agro_demo.owl` появится локально после запуска.
